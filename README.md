# job-tracker

A job search tracker for people who are applying to more places than they can
keep in their head. Every application moves through a pipeline, from a posting
you bookmarked to an offer you accepted (or a polite rejection), and the app
keeps the details, the dates and what you need to do next.

## Features

- **Pipeline board**: wishlist, applied, screening, interviewing, offer, and
  accepted / rejected / withdrawn. Drag cards between columns or within a column.
- **Table view** with search, status and tag filters, sorting and pagination.
- **Applications**: company, role, location, work mode, source, priority, salary
  range, the job posting URL and a snapshot of the job description.
- **Timeline** of status changes and interviews for each application.
- **Companies and contacts** next to the applications for them.
- **Interviews** with date and time in your time zone, type, prep notes and
  how it went.
- **Reminders** for follow-ups, with the ones due today and overdue on the
  dashboard.
- **Stats**: funnel conversion, response rate, time to first response and
  applications per week.
- **Accounts** with email confirmation and password reset.

## Architecture

```
browser ──websocket──> Phoenix (LiveView) ──Ecto──> PostgreSQL
                       one release, port 4000
```

It's a server-rendered monolith: every page is a LiveView, and the only
JavaScript is the LiveView client plus a small hook for drag and drop on the
board. The code is split into contexts under `lib/job_tracker`, each scoped to
the signed-in user:

| Context      | What's in it                                                       |
| ------------ | ------------------------------------------------------------------ |
| `Accounts`   | Users, sessions, tokens and preferences (generated by phx.gen.auth) |
| `Pipeline`   | Applications, status history, board ordering, tags and the table query |
| `Companies`  | Companies, looked up case-insensitively when typed on a form       |
| `Contacts`   | People at companies                                                |
| `Interviews` | Interviews, stored in UTC and shown in the user's time zone        |
| `Reminders`  | Follow-ups, with "today" computed in the user's time zone          |
| `Stats`      | Funnel, response rate and weekly counts (`Stats.Calculations` is pure) |
| `Export`     | CSV export, with protection against spreadsheet formulas           |
| `Demo`       | The demo account and its sample data                               |

The web layer lives in `lib/job_tracker_web`: one LiveView per page under
`live/`, shared components in `components/app_components.ex` and formatting
helpers in `format.ex`. `GET /health` checks the database and is used by the
Docker healthcheck.

How a few things work:

- **Status history.** Every create, edit, board move or status change that
  changes the status writes a `status_changes` row in the same transaction.
  The timeline and all the stats are built from it.
- **Funnel.** An application counts as having reached a stage if it ever got
  there or past it, so an application that went straight from applied to
  interviewing also counts for screening. Rejected and withdrawn keep the
  stage they had reached.
- **Response rate.** Applications that moved past the wishlist and then got
  any answer: a screen, an interview, an offer or a rejection.
- **Board order.** Each card has a position within its column. A move
  renumbers the target column in one transaction.

## Running with Docker

```bash
cp .env.example .env    # optional, the defaults work
docker compose up --build
```

Open <http://localhost:4408> and log in as **demo@example.com** /
**demo-password**. The demo account is created on the first start with a few
months of applications, interviews and reminders. Set `SEED_DEMO=false` in
`.env` to skip it.

The `app` container runs the migrations on start and has a healthcheck on
`/health`. Postgres is published on port 5448 for local tools. Both ports can
be changed with `APP_PORT` and `DB_PORT` in `.env`.

To start over with an empty database:

```bash
docker compose down -v
```

## Running locally

You need Elixir 1.17 or newer and PostgreSQL. The dev and test configs connect
to `localhost` with `postgres` / `postgres`; set `DB_HOST` to use another host.

```bash
mix setup               # deps, database, migrations, assets
mix phx.server          # http://localhost:4000
```

To use Postgres from the Docker setup, start only the database and point the
app at it:

```bash
docker compose up -d db
DB_HOST=localhost DB_PORT=5448 mix setup
```

To create the demo account locally:

```bash
SEED_DEMO=true mix run priv/repo/seeds.exs
```

## Tests and lint

```bash
mix test
mix lint                # format check and credo --strict
```
The tests need a running Postgres (the same one as for development works).
Context tests cover the business rules (pipeline moves and history, funnel and
response rate maths, time zones, reminders), and LiveView tests drive every
page.
